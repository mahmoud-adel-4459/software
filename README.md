# نظام شؤون العسكريين — سطح المكتب والشبكة الداخلية

الإصدار **0.2.0**: تطبيق Electron عربي، وخدمة HTTPS على Windows Server وقاعدة PostgreSQL مركزية. جهاز البوابة مقيد بوظائف البوابة حتى عند دخول مسؤول، والجهاز الداخلي يدير جميع الوحدات. التشغيل يعتمد على الشبكة الداخلية والخادم دون إنترنت.

تفاصيل الإنجاز وحدود التحقق في [حالة التنفيذ](docs/IMPLEMENTATION_STATUS.md)، والمتطلبات في [الخطة](DESKTOP_PLAN.md). النموذج القديم محفوظ في index.html وjs؛ العميل الجديد يبدأ من renderer/index.html ولا يستخدم بيانات التجربة.

## تطبيق سطح المكتب المتكامل (موصى به)

| الهدف | الأمر |
|--------|--------|
| **تشغيل يومي من المصدر** | `شغّل.cmd` أو `npm run play` |
| **بناء مثبت Windows + portable** | `بناء-التطبيق.cmd` أو `npm run build:integrated` |

بعد **التثبيت من Setup.exe** يفتح البرنامج تلقائيًا بوضع **play**: خادم HTTPS وقاعدة PGlite داخل `%LOCALAPPDATA%` — **بدون** تشغيل PostgreSQL أو `npm run server`. كلمة المسؤول في `...\Military Affairs Play\standalone\login.txt`.

للربط بخادم PostgreSQL على الشبكة: شغّل `Military Affairs.exe --remote` ثم اضبط العنوان وCA من شاشة الاتصال.

## الحزم

- artifacts/*Setup*.exe: مثبت العميل المتكامل (PGlite + خادم مدمج).
- artifacts/desktop-portable: نسخة محمولة؛ `تشغيل-محلي.cmd` للوضع المتكامل.
- artifacts/server-bundle: خادم Windows + PostgreSQL (وحدات متعددة / LAN).

خادم PostgreSQL المركزي اختياري للمتكامل؛ مطلوب فقط لوضع `--remote` أو نشر `server-bundle`.

المثبت الحالي غير موقع بشهادة ناشر Windows. تم فحص حزمة العميل للتأكد من عدم احتوائها على ملفات الخادم أو أداة إصدار الترخيص أو المفاتيح الخاصة أو .env.

## التطوير والبناء

### أوضاع التشغيل

| الوضع | الأمر | الواجهة | طباعة/PDF | قاعدة البيانات |
|--------|--------|---------|-----------|----------------|
| **تجربة كاملة (موصى به)** | `npm.cmd run demo` | Electron | نعم | Lab مؤقت (PGlite) |
| معاينة متصفح | `npm.cmd run preview:local` | Chrome/Edge | لا | مؤقت |
| إنتاج | `npm.cmd run server` + Electron | Electron | نعم | PostgreSQL |

لا تفتح `https://127.0.0.1:8443` في المتصفح للواجهة — هذا عنوان **API** فقط. التفاصيل في [scripts/LAB-AR.md](scripts/LAB-AR.md).

على PowerShell استخدم npm.cmd:

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd test
npm.cmd start
npm.cmd run demo
npm.cmd run pack:portable
npm.cmd run pack:server
npm.cmd run dist
```

## إعداد الخادم

1. ضع حزمة الخادم في مجلد محلي مثل C:\MilitaryAffairsServer خارج OneDrive، وجهز قاعدة PostgreSQL وحسابًا خاصًا بها.
2. انسخ .env.example إلى .env واضبط DATABASE_URL وSERVER_ID وعنوان الاستماع. استخدم معرف تثبيت ثابتًا وفريدًا.
3. اضبط ADMIN_PASSWORD بكلمة فريدة لا تقل عن 12 حرفًا للتجهيز الأول، ثم شغل npm.cmd run server:init. احذف كلمة التجهيز من .env بعد إنشاء المسؤول. تشغيل الأمر عند الترقية يطبق المخطط ولا يغير حساب المسؤول الموجود.
4. جهز شهادة HTTPS تحتوي اسم الخادم أو عنوانه في SAN، واضبط ملفات TLS في .env. استورد شهادة الجهة المصدرة في شاشة إعداد العميل. لا تعطل التحقق من الشهادة.
5. اعتمد الخادم والجهازين بالطريقة التالية. اضبط ملفات الترخيص والمفتاح العام في .env ثم شغل npm.cmd run server.
6. اسمح بمنفذ HTTPS المحدد، افتراضيًا 8443، للجهازين فقط. تبقى قاعدة البيانات متاحة للخدمة ولا تحتاج مشاركة ملفات أو فتح منفذها للعملاء.

### خدمة Windows

يوجد قالب server/service.xml.example وسكربت server/install-service.ps1. احصل على WinSW من مصدره الرسمي، ثم شغل السكربت بصلاحيات مسؤول على الخادم:

```powershell
.\server\install-service.ps1 -WrapperPath C:\Installers\WinSW.exe -InstallDirectory C:\MilitaryAffairsServer
```

السكربت يسجل خدمة تلقائية بحساب LocalService ويضبط صلاحيات الحزمة و.env. امنح حساب الخدمة قراءة ملفات TLS وكتابة مجلد النسخ قبل بدء الخدمة. السكربت لا يثبت Node أو PostgreSQL ولا يعدل الجدار الناري، ولم يشغل على خادم فعلي هنا. راجع [توثيق WinSW](https://github.com/winsw/winsw/blob/v2/doc/xmlConfigFile.md).

## التفعيل بواسطة مالك البرنامج

1. على كل عميل، ومن حساب Windows الذي سيشغله، صدّر طلب اعتماد الجهاز من شاشة الإعداد. مفتاح العميل محمي بواسطة Windows DPAPI.
2. على الخادم شغل npm.cmd run server:activation لتصدير server-request.json. يحتوي معرف الخادم وبصمته العامة.
3. على جهاز المالك فقط أنشئ مفتاح إصدار بواسطة أداة tools/license.cjs؛ راجع مساعدتها. احتفظ بالمفتاح الخاص خارج الحزم والخادم.
4. جهز بيان الترخيص بــ serverId وserverFingerprint من طلب الخادم وinstallation وdevices: جهاز بدور gate وآخر internal، ومعرف ومفتاح عام لكل منهما. استخدم أداة الإصدار لتوقيع البيان.
5. ضع الترخيص والمفتاح العام فقط على الخادم. نسخ التطبيق إلى جهاز ثالث لا يمنحه اعتمادًا.

الخادم يتحقق من بصمة Windows MachineGuid ومعرف التثبيت؛ نقل الخدمة إلى Windows آخر يحتاج إعادة إصدار الترخيص. احتفظ بنفس SERVER_ID عند نقل النسخ الاحتياطية. هذه حماية برمجية وليست TPM، ولا تضمن مقاومة تعديل البرنامج أو استنساخ Windows كاملًا بواسطة مسؤول النظام.

## النسخ والاستعادة

اضبط BACKUP_KEY_HEX بمفتاح عشوائي من 64 خانة hex وBACKUP_DIRECTORY بمجلد محلي قابل للكتابة بواسطة الخدمة. احتفظ بالمفتاح خارج الخادم بشكل آمن؛ فقدانه يمنع فك النسخ. BACKUP_RETENTION_DAYS بين 7 و365 وافتراضيه 30.

النسخة مشفرة وتشمل البيانات والمستخدمين والمرفقات، ولا تشمل الترخيص أو شهادات TLS أو مفاتيح الإصدار. المجدول ينشئ نسخة كل 24 ساعة من بدء الخدمة ويحذف النسخ المولدة القديمة بعد نجاح النسخ. احفظ نسخة خارج قرص الخادم أيضًا.

من الجهاز الداخلي تستطيع إنشاء نسخة وتنزيلها، أو استيراد ملف ثم معاينة محتواه. الاستعادة تحتاج كلمة مرور المسؤول وتأكيد RESTORE، وتمنع الطلبات المتزامنة، وتنشئ نسخة أمان قبل التغيير، وتنفذ داخل معاملة ثم تبطل الجلسات. تحتاج الاستعادة نفس مفتاح التشفير ومعرف الخادم.

حد النسخة 32MB مضغوطة ومشفرة و128MB بعد الفك؛ للبيانات الأكبر جهز نسخ PostgreSQL تشغيلية مناسبة.

## نقل بيانات النموذج القديم

افتح legacy-export.html من نفس أصل الصفحة ونفس المتصفح الذي يحتفظ ببيانات النموذج. يصدر بيانات الإصدار القديم دون كلمة المرور القديمة. قد يفصل المتصفح تخزين صفحات file://؛ إذا لم تظهر البيانات استخدم التصدير من الصفحة الأصلية في بيئتها نفسها.

من شاشة النسخ والنقل على الجهاز الداخلي اختر الملف، راجع الأعداد والأخطاء والتحذير إذا كانت بيانات تجريبية، ثم أكد IMPORT. الاستيراد يحفظ الأفراد والصور والحركات والكانتين واللياقة، بما فيها نتائج اللياقة النصية دون اختراع درجات. لا ينقل حسابات الدخول أو إعدادات الوحدة القديمة؛ راجع الإعدادات بعد النقل.

التكرار والأرقام والتواريخ غير الصالحة تمنع النقل الجزئي. خذ نسخة احتياطية أولًا إذا كانت قاعدة الوجهة تحتوي بيانات.

## الترقية من 0.1

أوقف الخدمة واتصالات العملاء وخذ نسخة PostgreSQL قبل ترقية المخطط. احتفظ بملف .env والشهادات وهويات العملاء. حدّث الملفات وشغل server:init لتطبيق الترحيلين 002 و003؛ لا تحتاج كلمة تجهيز جديدة إذا كان المسؤول موجودًا.

أصدر طلب اعتماد للخادم وأعد إصدار الترخيص ليحتوي serverFingerprint، لأن ترخيص 0.1 القديم لا يحتويه. حدّث العملاء مع الاحتفاظ بمجلد بياناتهم، ثم راجع الأعداد والحسابات واختبر النسخ والاستعادة قبل التشغيل الفعلي.

## الاختبارات وحدود التشغيل

npm.cmd test يشغل اختبارات التوقيع والصلاحيات والواجهة والوحدات والنقل والنسخ والتراجع. يستخدم pg-mem لبعض اختبارات API وPGlite للمعاملات؛ الأخير باتصال واحد. للتحقق من PostgreSQL مستقل اضبط TEST_DATABASE_URL على قاعدة اختبار؛ الاختبار ينشئ مخططًا معزولًا ويحذفه ويتحقق من التزامن.

الواجهة اختبرت عبر jsdom مع محاكاة الوظائف الأصلية للطباعة وحفظ الملفات. سياسة Application Control الحالية تمنع تشغيل Electron هنا؛ بناء المثبت لا يثبت عمل النافذة أو الطابعة.

يلزم اختبار Windows Server والجهازين وUSB والطباعة وPDF وانقطاع الشبكة والتعافي في بيئة التشغيل. لم تثبت الخدمة أو الشهادات أو قاعدة البيانات الفعلية في هذه الجلسة.
